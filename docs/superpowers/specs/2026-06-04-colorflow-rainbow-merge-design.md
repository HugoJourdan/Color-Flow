# Color Flow + Rainbow FontView — Merge Design

**Date:** 2026-06-04
**Status:** Draft for review
**Repo:** `Color-Flow` (the surviving bundle is `Color Flow.glyphsPalette`)

## Context

The user maintains two Glyphs 3 plugins that already revolve around the same 12
native color labels and the same `colorNames.txt` file:

- **Color Flow** (`.glyphsPalette`) — sidebar palette. Maps the 12 colors to
  ordered workflow *steps*; checkboxes set a layer's color (the color is the step
  preceding the first unchecked box), and progress bars/counters track how many
  glyphs have reached each step. Ships 12 keyboard-shortcut scripts. Recently
  stabilized: a shared, tested `colorflow_colornames.py` module, a shortcut
  generator, and fixes for the broken shortcuts, a colorNames load crash, and
  self-healing of corrupt persisted counts.
- **Rainbow FontView** (`.glyphsPlugin`, GeneralPlugin) — reorders the Font View
  into labelled color *sections* by rewriting the `glyphOrder` custom parameter.
  Clean architecture: pure `rainbow_core.py` (parse/build/render), a vanilla
  `rainbow_settings.py` window (color source + label editing), debounced +
  dirty-checked rebuilds, non-destructive `glyphOrder` backup/restore, live
  key-file reload, File-menu toggle + Settings items.

Both read the *same* `colorNames.txt` but with **separate parsers** (Rainbow:
int keys `0-11` + a `None` bucket + emoji default labels + order; Color Flow:
string keys `"0".."11"`). They are separate bundles, so they cannot import each
other.

## Goal

Merge into a **single `Color Flow.glyphsPalette` bundle** that provides:
1. the Color Flow palette (checkboxes, progress, shortcuts) — unchanged model;
2. Rainbow's Font-View grouping (toggle on/off, layer/glyph color source,
   non-destructive backup/restore);
3. **inline label rename** in the palette (double-click a label) that writes
   `colorNames.txt`, so the palette *and* the Font-View sections relabel live;
4. one shared color-name module as the single source of truth for the palette,
   the Font-View grouping, and the 12 shortcut scripts.

The standalone **Rainbow FontView plugin is retired** (disabled/removed by the
user). Its separate Settings window is dropped — inline rename + an action-menu
color-source toggle replace it. The merged plugin keeps the name **"Color Flow"**.

## Non-goals

- No change to the per-layer userData shape (`com.hugojourdan.ColorFlow` stays
  string-keyed `{"0".."11": bool}`) — avoids migrating existing fonts.
- No new features beyond those above (the broader Color Flow feature wishlist —
  scoped progress, CSV/JSON reports, batch ops — stays out of this merge).
- Not a rewrite of Rainbow's grouping algorithm; it is ported as-is.

## Architecture

One bundle, four Python units in `Contents/Resources/`:

```
Color Flow.glyphsPalette/Contents/Resources/
├── plugin.py        # PalettePlugin: palette UI + menu items + wiring
├── colornames.py    # ONE source of truth (merges colorflow_colornames + rainbow_core)
├── fontview.py      # Font-View grouping engine (ported from Rainbow plugin.py)
└── (generated by tools/generate_shortcuts.py → the 12 shortcut scripts embed colornames.py)
```

A `PalettePlugin` has full API access, so one bundle can host the sidebar palette
**and** register File-menu items **and** rewrite `glyphOrder`. Confirmed against
Rainbow (a GeneralPlugin doing the grouping) — the same calls work from a palette.

### `colornames.py` (single source of truth)

Folds together the two parsers. Public surface:

- Constants: `COLOR_ORDER`, `NAME_TO_INDEX`, `COLOR_NAMES` (reverse), `KEY_FILE_NAME`,
  `NONE_TOKEN`, `NO_COLOR = -1`, `DEFAULT_COLOR_NAMES` (the emoji default file).
- `parse_color_names(text)` → canonical mapping. Internally keyed by **int**
  index (matches Glyphs' native `.color`) plus the `NO_COLOR` bucket, preserving
  file order and collecting `rejected` unknown names (Rainbow's tolerant parser).
- String-key adapters for the palette/shortcuts: `meaning_str(parsed)` →
  `{"0".."11": label}` (drops `None` bucket), keeping the existing palette/shortcut
  code and persisted data unchanged.
- Palette helpers (already built + tested): `layer_color_for_state`,
  `count_states`, `default_state`, `visible_labels`.
- Font-view helpers (from `rainbow_core`): `label_for`, `section_order`,
  `build_glyph_order`, `render_key_file`.
- Path/IO: `resolve_key_file`, `ensure_key_file` (best-effort, no write-through a
  broken symlink), `load_meaning`, using **`GSGlyphsInfo.applicationSupportPath()`**
  for the support dir (replaces `os.path.expanduser`, which returned a literal
  `~` at plugin-load time and caused a crash). The GlyphsApp import is isolated to
  a tiny path helper so the rest of the module stays pure and unit-testable; the
  helper degrades to `expanduser`+`$HOME` outside Glyphs (for tests).

All of the above stays under TDD with the existing `tests/` suite.

### `fontview.py`

Ports Rainbow's grouping engine as a plain helper class driven by the palette:
`enable(font)`, `disable(font)`, `rebuild(font)`, `is_dirty(font)`, debounce, and
the `glyphOrder` backup/restore. Reuses `colornames.build_glyph_order`/
`section_order`. Keeps Rainbow's userData keys verbatim
(`hugojourdan.RainbowFontView.enabled` / `.savedGlyphOrder` / `.hadGlyphOrder` /
`.labelUsed`) and tempData snapshot keys, so a font already grouped by the
standalone Rainbow stays consistent after the merge.

### `plugin.py` (the palette)

- Hosts the palette UI (below) and, in `start()`, installs one File-menu item: a
  checkmark **"Color Flow: Rainbow Font View"** toggle (the same on/off also lives
  in the palette action menu). The separate Settings window is retired. Tears the
  menu item down on reload like Rainbow does (tracking the active instance, since
  the callback registry holds a strong ref).
- One `UPDATEINTERFACE` handler does **both** jobs: refresh the palette (dirty-checked,
  widgets reused — the perf rewrite) and, when grouping is enabled, run Rainbow's
  cheap dirty-check + debounced `glyphOrder` rebuild.
- Folds in the outstanding Color Flow fixes (see Phase 1).

## UI design

Row layout (palette is ~160px wide), widgets created **once** and mutated on update
(replaces the current teardown/rebuild-every-fire):

```
 ▌ [✓]  ✎ 🦊 Orange            12/1147
 │   │    │                      │
 │   │    │                      └ count (or ✅ at 100%)
 │   │    └ clickable label (TextBox); single-click toggles, double-click edits
 │   └ checkbox box only (no title)
 └ color tag swatch
```

- **Single-click** anywhere on the row toggles the step (current behavior).
- **Double-click the label** swaps it to a vanilla `EditText` prefilled with the
  current label (emoji + text). Enter or focus-loss saves: parse → update meaning →
  `render_key_file` → write `colorNames.txt` → reload (palette relabels, Font-View
  re-sections if enabled). Escape cancels.
- Double-click detection: an `NSClickGestureRecognizer` (`numberOfClicksRequired
  = 2`) on the label view, with single-click still routing to the checkbox toggle.
- Header: master name + an action button (`⋯`). Action menu: existing items
  (Setup, Reset, Generate Smart Filters [fixed predicate], Copy to Master, Report
  toggle, Open Docs) **plus** "Rainbow Font View" on/off and a "Color source:
  Layer / Glyph" choice (drives grouping).

## Migration & coexistence

- `colorNames.txt`: already shared and already in Rainbow's emoji format; the
  unified parser reads it unchanged. Default-file creation uses Rainbow's emoji
  `DEFAULT_COLOR_NAMES`.
- Per-layer `com.hugojourdan.ColorFlow` userData: unchanged (string keys).
- Aggregate counts: self-healing recompute already handles corrupt/missing/legacy
  values (e.g. a serialized `None` → `"<null>"`).
- Rainbow state: adopted verbatim (enabled / saved order). A font grouped by the
  old plugin keeps working; toggling off restores the original `glyphOrder`.
- **Conflict guard:** if the standalone Rainbow FontView is still installed and
  enabled, two `UPDATEINTERFACE` handlers fight over `glyphOrder`. On `start()`
  the merged plugin detects the standalone bundle (by its menu items / bundle id)
  and shows a one-time message telling the user to disable it. README documents this.

## Phasing (each phase independently testable in Glyphs)

- **P1 — Stabilize the palette.** Finish the outstanding Color Flow fixes that the
  merge builds on: widget-reuse + dirty-signature rewrite of `update()`/
  `Update_Plugin_UI` (replaces teardown-per-fire and the dead `self.Glyphs` typo),
  Smart-Filter predicate fix, deepcopy-on-copy, Setup edge case, narrowed excepts
  with logging, remove the debug `print`/instrumentation, Info.plist polish.
- **P2 — Unify `colornames.py`.** Fold `rainbow_core` into the shared module;
  adopt `GSGlyphsInfo` path; keep all existing tests green and add tests for the
  folded-in functions (`build_glyph_order`, `section_order`, `render_key_file`,
  `parse` int/None semantics).
- **P3 — Font-View grouping.** Add `fontview.py` + the File-menu toggle + action-menu
  on/off + color source, backup/restore/debounce/dirty, conflict guard.
- **P4 — Inline rename + row redesign.** Separate checkbox/label, double-click edit,
  write-back, live reload across palette + Font View.
- **P5 — Finish.** Migration polish, retire Rainbow bundle (user-facing guidance),
  README rewrite covering both halves, version bump, Plugin Manager metadata.

## Testing

- **Unit (pytest, outside Glyphs):** all of `colornames.py` — parsing (int/None/
  order/rejected/blank/symlink fallback), `layer_color_for_state`, `count_states`,
  `build_glyph_order`/`section_order`/`render_key_file`, round-trip rename. The
  GlyphsApp path helper is the only impure seam and is injectable.
- **Manual (in Glyphs, per phase):** palette renders + toggles + counts; shortcuts
  toggle + self-heal; Rainbow grouping on/off restores original order; double-click
  rename relabels palette + sections live; multi-master + unsaved-font + no-font +
  empty-font edge cases; conflict guard fires when standalone Rainbow present.

## Risks / open questions

- **Double-click vs single-click** in vanilla needs a gesture recognizer; if it
  proves flaky, fall back to a per-row `✎` affordance (decided against in design,
  kept as a backstop).
- **Palette driving `glyphOrder`** is slightly unconventional but verified feasible.
- **One UPDATEINTERFACE doing both jobs** must stay cheap; the dirty-checks for
  palette and grouping are independent and both O(selection).
- Bundle-detection for the conflict guard depends on the standalone bundle id /
  menu titles staying stable.
