# Color Flow — Feature R&D

Color Flow turns layer-colour labels into a workflow progress system. Right now it's a still frame: it shows *where* glyphs are, never *when* work happened, *whether* a step's craft criterion is actually met, or whether an *exported instance* is ready. These 24 ideas, scored and ranked, push Color Flow from a tracker toward a production QA and pacing tool — without breaking the non-destructive, single-source-of-truth discipline the codebase already enforces.

> Generated by a 37-agent R&D workflow (map code + Glyphs API → ideate across 6 lenses → dedup 36→25 → skeptical feasibility judge → synthesize). API hooks and line numbers were verified against the source and the GlyphsCore headers.

## ⭐ Top 3 picks

### 1. Burndown + Forecast — *"are we on track to ship Bold this week?"*
**Pitch:** A Trend tab plus a stats strip that reads pace per master — `Velocity: ~38 glyphs/week`, `Remaining: 412`, `Forecast: done ≈ 2026-07-18 (±5 days)` — backed by a per-step burndown chart.

**Why it matters:** Foundry production plans release dates. Today the dashboard answers "what changed since last run" but gives zero sense of pace; a 2000-glyph family needs a trend and a hedged ETA to schedule around. This is the difference between a status page and a planning instrument.

**Build sketch:** Extend the snapshot store in `colorflow_dashboard.py` from a single overwritten snapshot to a dated series `'…DashboardHistory'[filepath] = {ISOdate: {master_id: per_step_counts}}` — counts only, same-day collapse, ~180-day cap. Auto-capture by adding a render-free `record_snapshot(font)` to the already-wired `documentDidSave_` observer (`plugin.py:440`). Velocity/ETA stay pure, GlyphsApp-free, unit-testable functions (diff final-step counts over a trailing window, linear fit, ± band from rate variance). Charts are hand-rolled inline-SVG polylines/`<rect>` stacks in `colorflow_assets.py` DASHBOARD_JS — same precedent as the heatmap, zero new deps.

**Effort:** L. **Risk:** History only accrues from install (label "recording started <date>"); cadence is tied to saves so a designer who never saves gets sparse data; linear ETA undercounts slow late-QA glyphs — hence the mandatory ± band, never a hard date.

*This is also the substrate for the per-glyph journey sparkline (#12) and the CSV/JSON history export (#22).*

### 2. Pre-export QA Panel — *connect workflow progress to what actually ships*
**Pitch:** A `⋯`-menu panel that, per active instance, reports how many glyphs are **not** at the final step on the masters that instance interpolates from — with a drill-down list and "Open in tab."

**Why it matters:** Color Flow tracks masters, but a foundry exports *instances*. A glyph can be green on every master yet an instance ships glyphs that never finished on a master it actually depends on. Nothing today bridges workflow state to instance readiness — QA happens by eye after generating fonts. Since the final step *is* the user-defined "ready to export" colour, this is a genuine readiness gate.

**Build sketch:** New `colorflow_qa.py`. `GSInstance.instanceInterpolations` is a public `{master_id: coefficient}` NSDict — the exact instance→contributing-masters map, keyed by the *same* master IDs the dashboard already uses. No axis-interval math needed. A glyph is "not ready" if any contributing master's `layer.color` isn't the last `order` entry — reuse the existing "finished" test from `_outline_paths`. Honour `instance.active`; render with vanilla `List`/`Window`; "Open in tab" via `font.newTab`.

**Effort:** M. **Risk:** `instanceInterpolations` is nullable and can be stale under `manualInterpolation` — guard `None`/call `updateInterpolationValues`, treat nonzero coefficient as contributing. Advisory-only in v1 (export-blocking is #4).

### 3. Definition-of-Done Gates — *stop "100%" from being a lie*
**Pitch:** Each colour step can carry an optional machine-checkable gate (paths closed, ≥N anchors, components aligned, LSB/RSB match metrics key, width ≠ 0). Toggling a step ON runs that gate against the selected layer(s); on failure the checkbox flashes red with a reason ("3 open paths") instead of advancing.

**Why it matters:** Step labels are pure self-report. A designer marks "Outline done" green over open paths or a broken metrics key, so the dashboard's 100% can't be trusted at QA time. Gates make the green signal *mean* something — opt-in per colour, advisory or strict per step.

**Build sketch:** `colornames.txt` gains an extended suffix (`darkGreen=Outline done @gate:closed,anchors>=2`) parsed in `colornames.py`; backward-compatible (no `@gate` = no gate). In `plugin.py` `CheckBox_Callback`, run the gate before applying `layer.color`, inside the existing `disableUpdateInterface`/`enableUpdateInterface` block (lines 953–995). Predicates are all confirmed Python-accessible: `path.closed`, `layer.isAligned`, `layer.widthMetricsKey`/`leftMetricsKey` + `layer.LSB`/`RSB`, `layer.anchors`, `layer.width` — plus the cleaner `layer.metricsKeysOutOfSync`. Per-row gate editor in `settings_panel.py`.

**Effort:** L (leaning L+). **Risk:** The real friction is the data model, not the API — `parse_color_names` currently keeps everything after the first `=` as the label, so `@gate:` lands *inside* the label string; you must split it out and thread a new gate field through `visible_labels`/`count_states` and every `{indexStr:label}` consumer. Predicates must stay cheap (runs on every toggle); overlap heuristics are approximate — under-promise ("looks open"), never assert. Mandatory advisory escape hatch.

## 🏗️ Flagship features

**Export Lint Gate (#4, M).** The hard counterpart to #2: at export, scan every exporting glyph's `layer.color` against the workflow order; warn (default) or block (strict) on glyphs below the "done" step. Two paths, both verified: post-hoc warning via `Glyphs.addCallback(self.on_exported, DOCUMENTEXPORTED)` (fires *after* write — honest limit), and *true* blocking via a sibling `Color Flow Lint.glyphsFilter` implementing `processFont:instance:error:` (`GlyphsFilterProtocol.h:142`) that imports the shared `colornames.py` and returns `NO` + `NSError`. **Risk:** No pre-export notification exists in the Python API, so the sibling filter is genuinely required for blocking; custom-param export filters only run if added to the instance (mitigate with an inject button); `NSUserNotification` is deprecated — pick the path per macOS version.

**Right-click "Set workflow step" (#6, M).** A native `Color Flow ▸` submenu on any Font/Edit-View selection listing visible steps by real label, plus "Advance one step" / "Clear" — bulk-applying a step to a multi-selection in one undoable batch, which is *impossible* today. Register `GSContextMenuCallbackName` (`GSCallbackHandler.h:30`, Python-exposed as `CONTEXTMENUCALLBACK`); `contextMenuCallback:forSelectedLayers:event:` hands you the layers directly. **Risk:** No mekkablue precedent for this callback from a palette-origin plugin — needs a Glyphs smoke test (try/except, degrade to reporter's `addMenuItemsForEvent:`). `layer.color` registers undo natively so one Cmd-Z mostly works, but per-glyph layer edits use each glyph's own undo manager, not `font.undoManager`.

**Smart Filter pack (#14, M).** A menu action builds a "Color Flow ▸" Smart Filter group, one predicate filter per step, living natively in the Glyphs sidebar and surviving sessions. Verified against a hand-built filter: the font-level `Filters` customParameter with `predicate:"colorIndex == 6"` works, compound "at or before" is `colorIndex <= N`, folder nesting key is `subGroup` (not `subItems`), "no colour" is `colorIndex == 255` (not 0 — that's Red). **Risk:** Sidebar `colorIndex` filters the *glyph*'s colour, while Color Flow's model is per-*layer* — backlog filters only line up if glyph colour mirrors the active layer's step (an explicit model-mapping decision).

**Project Hub (#8, L).** A read-only rollup over all open documents (`Glyphs.documents`): one row per font × master with per-step bars and a family rollup ("Family at Spacing: 71%"). The data layer is already font-parametric — `build_master_glyph_colors(font)` and `master_counts()` each read that font's own `colorNames.txt` via `resolve_key_file`. Deep-links already encode per-font path+glyph+layer. **Risk (material):** Fonts may have *non-aligned* `colorNames.txt` — you cannot assume one shared step order. Group by colour index 0–11 (the only stable cross-font key) and label per-font, or Sans "step 3 = Spacing" silently mismatches Serif "step 3 = Kerning" and the family number is confidently wrong.

**Shareable workflow profile (#9, M).** Export/import a self-contained `.colorflow` file (colour order, labels, visibility, free/step mode, Rainbow source, the 12 `LabelColors` RGBA) with a **diff** on import ("your order differs: Brown before Yellow; house standard is the reverse") so it's conflict-surfacing, not silent overwrite. Ship 2–3 presets. `settings_panel._save()` is already 90% of the import path. **Risk:** `FREE_KEY` + `LabelColors` are app-global so import flips them for *all* open fonts (vs per-font `MODE_KEY` userData); `LabelColors` needs a restart for native views; snapshot the old file so import is undoable.

**Review Queue (#10, M).** Click a step's count badge to select/walk every glyph at that step — the reverse of today's read-only palette. The count badge is already a separate TextBox (`str(color)+"count"`), so the gesture attaches with no collision with the rename gesture. `font.newTab('/'.join(names))` is rock-solid; mode-aware glyph-set derivation already exists. **Risk:** `font.selection` setter for Font-View highlight is shakier than `newTab` — keep `newTab` primary, Font-View select behind a modifier; guard `font.parent` None; cap large tabs.

## 🌙 Moonshots

**Workflow Recipes (#5, XL).** Per-script/category step routing so a mark counts 100% at its last *relevant* step instead of stalling on an irrelevant "spacing". Predicates (`glyph.category`/`subCategory`/`script`/`case`, `font.filterGlyphs`) all real; parser stays GlyphsApp-free. **Key unknown:** This rewrites the *counting denominator* — today's `len(order)` global sum becomes per-glyph-weighted aggregation in both palette bars and dashboard `master_counts`. The no-recipe path must stay byte-identical, and palette/dashboard must never disagree. High value, but it touches the core invariant.

**All-Masters Matrix in the palette (#16, L).** Per-master step cells in each row so you see "a" spaced in Light but not Bold without switching masters. Data hooks are real and already master-parameterised. **Key unknown:** the *surface*. A `.glyphsPalette` is a fixed ~160px dock column — there's no API to widen it, only the height constraint animates. N cells in 160px is fine as dots for 2–4 masters, genuinely cramped at 6+. The offline dashboard already owns this wide grid; the matrix metaphor fights the medium.

**Sign-off Lock (#15, L).** Freeze finished glyphs at the final step via native lock; demoting unlocks. `GSLayer.locked` exists (`GSLayer.h:435`) and `fontview.py`'s userData ownership-tagging is a direct precedent. **Key unknown (blocker-grade):** every lock precedent in the corpus freezes the *glyph* (`layer.parent.locked`), not the layer — zero examples of `GSLayer.locked=True` blocking Edit-View editing. If Glyphs' editable-lock is glyph-level (likely), the headline *per-master* sign-off collapses and the feature needs a redesign around `GSGlyph.locked`. Verify round-trip + Edit-View enforcement *before* committing.

**Per-glyph activity timeline from `lastChange` (#24, M).** "Show me everything edited since Monday" / "stale at step 3 for 3 weeks" with no history needed. **Key unknown — partly a no:** `GSGlyph.lastChange` is per-*glyph*, not per-layer, so a per-cell recency dot in the steps×masters heatmap is impossible — every master's cell shows the same glyph-level age. `GSLayer.lastOperation` is *not* an edit timestamp (it's interpolation-cache invalidation). And foundries commonly disable "Write lastChange," yielding all-None. Frame honestly as glyph-level edit-recency or drop it.

## Honest constraints

- **No pre-export hook in Python.** `DOCUMENTEXPORTED` fires *after* the file is written, so the palette alone can only warn post-hoc. Genuine export *blocking* (#4) requires shipping a sibling `.glyphsFilter` with `processFont:instance:error:` — not optional polish.
- **The palette is a fixed-width dock column (~160px).** Only the height constraint is animatable; there is no API to widen the inspector column. Anything needing horizontal room per master (#16) is cramped at >6 masters — the wide steps×masters grid belongs in the offline dashboard.
- **Editable-locking is almost certainly glyph-level, not layer-level.** The entire corpus locks `layer.parent` / `GSGlyph`; no evidence `GSLayer.locked` blocks Edit-View editing. Per-*master* sign-off (#15) is unproven and the evidence points against it.
- **Recency is per-glyph only, and history starts at install.** `lastChange` has no per-layer granularity and is often disabled in foundry setups (#24). All trend/forecast/journey features (#1, #12) accrue data only from install forward and are tied to save cadence — they're empty for the first weeks and sparse for designers who rarely save. Notification Center (`NSUserNotification`) is deprecated; a palette may lack the bundle id `UNUserNotification` needs — keep the in-palette banner as the real channel and OS posts as best-effort.
